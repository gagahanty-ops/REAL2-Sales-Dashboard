# Отключение и возврат публикации в Google Sheets

Публикация останавливается мгновенно и в одном месте: флаг
`sheet_publish_enabled` в таблице `system_controls`. Пока он выключен, код не
читает ключ сервисного аккаунта и не создаёт клиента Google.

## Немедленная остановка

```sql
update system_controls
set enabled = false, reason = 'инцидент <описание>', updated_at = now()
where key = 'sheet_publish_enabled';
```

Дополнительно можно убрать `SHEET_PUBLISH_ENABLED=true` из файла окружения и
перезапустить воркер: любой из двух переключателей достаточно, чтобы запись
стала невозможной.

## Когда система отключает публикацию сама

- раскладка копии изменилась (`E_SHEET_LAYOUT_MISMATCH`);
- обратное чтение не совпало с отправленным (`E_SHEET_UPSTREAM`);
- целевая таблица оказалась защищённой (`E_SHEET_PROTECTED`).

Во всех случаях предыдущее содержимое копии остаётся нетронутым, попытка
записывается со статусом `blocked` или `failed`, и открывается критическое
оповещение.

## Возврат публикации

1. Понять, что именно изменилось в копии: сравнить листы и размеры сетки.
2. Привести копию к ожидаемому виду **или** перевести цель обратно в
   `validated` и заново задать диапазоны.
3. Прогнать проверку раскладки: `POST /api/sheets/targets/{id}/validate`.
4. Активировать цель: `POST /api/sheets/targets/{id}/activate`.
5. Включить флаг вручную:

```sql
update system_controls
set enabled = true, reason = 'проверено <кем>, <дата>', updated_at = now()
where key = 'sheet_publish_enabled';
```

Ни миграция, ни развёртывание, ни тест, ни агент этот флаг не включают.

## Чего делать нельзя

- вписывать оригинальную таблицу как цель: идентификатор защищён константой в
  коде и проверкой в базе, обойти их нельзя;
- выдавать сервисному аккаунту доступ к оригиналу;
- редактировать записи `sheet_publications`: они неизменяемы и служат
  доказательством того, что и когда было записано.
