# Выход в production и включение публикации

Этот документ описывает два отдельных решения. Ни одно из них не выполняется
кодом, миграцией, тестом или агентом.

## Решение 1. Включить синхронизацию

Предусловия:

- теневая приёмка пройдена (`docs/runbooks/shadow-acceptance.md`);
- письменное подтверждение поддержки amoCRM о допустимости внешней интеграции;
- бэкапы включены, репетиция восстановления пройдена.

Процедура:

1. Владелец выставляет `SYNC_ENABLED=true` в файле секретов воркера.
2. Включает флаг в базе:
   `update system_controls set enabled = true, reason = '<кто, дата>' where key = 'sync_enabled';`
3. Наблюдает `/system` и `/sync` в течение часа: свежесть, ошибки, оповещения.

Откат — обратная операция; данные при этом не теряются.

## Решение 2. Включить публикацию в копию

Предусловия:

- копия создана вручную владельцем, доступ сервисному аккаунту выдан **только
  на копию**;
- цель зарегистрирована, диапазоны заданы, проверка раскладки пройдена, цель
  активирована;
- прогон `pnpm test:security` на боевом образе прошёл;
- владелец письменно принял отчёт по итогам теневого периода.

Процедура описана в `docs/runbooks/sheet-publication-disable.md` (раздел
«Возврат публикации»). Первая публикация выполняется в присутствии владельца,
сразу после неё сверяются контрольная сумма и содержимое копии.

## Что проверяется перед вердиктом GO

| Доказательство | Где хранится |
| --- | --- |
| Теневая сверка по дням | `docs/runbooks/release-evidence/` |
| Репетиция восстановления | вывод `scripts/verify-backup-restore.sh` |
| Подтверждение amoCRM | письмо владельца |
| Подпись владельца под приёмкой | `docs/runbooks/release-evidence/` |
| Прогон всех гейтов на боевом образе | лог CI или ручного прогона |

Вердикт GO разрешает провести окно изменений. Сам по себе он не включает
`sheet_publish_enabled` и не меняет учётные данные.

## Чего этот выпуск не делает никогда

- не пишет в amoCRM;
- не изменяет оригинальную таблицу;
- не включает внешние флаги автоматически при развёртывании.
