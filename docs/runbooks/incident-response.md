# Разбор инцидентов REAL2

Все оповещения приходят с кодом и идентификатором запроса. Начинать всегда с
`/system`: там видно готовность, свежесть и открытые оповещения.

## Общий порядок

1. Зафиксировать код оповещения и `trace_id`.
2. Проверить, что отчёт всё ещё показывает последний утверждённый снимок:
   пустой экран и устаревший снимок — разные состояния.
3. Остановить внешние действия, если причина неясна: выключить
   `SHEET_PUBLISH_ENABLED`, при необходимости `SYNC_ENABLED`.
4. Устранить причину, дождаться автоматического закрытия оповещения.
5. Записать в журнал, что произошло и что изменилось.

## Коды и первые шаги

| Код | Что значит | Первый шаг |
| --- | --- | --- |
| `database_unreachable` | база недоступна | проверить инстанцию и сеть; отчёт недоступен |
| `snapshot_missing` | утверждённого снимка нет | проверить `/quality`: снимок блокируют проблемы качества |
| `sync_stale` | синхронизация отстаёт больше 10 минут | посмотреть `/sync`, последние прогоны и ошибки |
| `sync_failing` | пять неудач подряд | проверить токен amoCRM и лимиты API |
| `quality_blocking` | есть непринятые блокирующие проблемы | разобрать список на `/quality` |
| `amo_token_expiring` | токен истекает менее чем через сутки | обновить интеграцию в настройках amoCRM |
| `sheet_layout_drift` | раскладка копии изменилась | см. `docs/runbooks/sheet-publication-disable.md` |
| `sheet_checksum_mismatch` | запись не сошлась при обратном чтении | публикация уже отключена автоматически |

## Что инцидент не меняет

- amoCRM и оригинальная таблица не изменяются ни при каком сценарии;
- утверждённые снимки не переписываются и не удаляются;
- принятие оповещения фиксирует, кто его увидел, но не закрывает причину.
