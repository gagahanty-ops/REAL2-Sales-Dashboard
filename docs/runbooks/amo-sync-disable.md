# Аварийное отключение amoCRM sync

Цель процедуры — сначала остановить новые сетевые обращения и публикацию,
затем сохранить доказательства и только после этого отзывать доступы.

## Немедленная остановка

1. В secret/config store установить:

   ```text
   SYNC_ENABLED=false
   SHEET_PUBLISH_ENABLED=false
   ```

2. Перезапустить/остановить worker, чтобы новое окружение применилось. Web можно
   оставить доступным для чтения уже сохранённых данных.
3. Через привилегированную административную DB-сессию выключить оба контроля:

   ```sql
   begin;
   update public.system_controls
   set enabled = false,
       reason = 'emergency shutdown; see incident record',
       updated_at = now()
   where key in ('sync_enabled', 'sheet_publish_enabled');
   commit;
   ```

4. Убедиться, что worker сообщает disabled/idle и число новых amoCRM-request в
   audit после времени отключения равно нулю. Не включать флаги для проверки.

## Сохранение доказательств

- Зафиксировать время по Москве, commit SHA и инициатора отключения.
- Сохранить sync run ID, queue ID, безопасные trace ID и статусы последних
  запусков. Не копировать токены, query/body, телефоны, имена и raw payload.
- Зафиксировать последний успешный snapshot/checksum и причину инцидента.
- Экспортировать только безопасную выборку audit: method, normalized path,
  status, duration, trace ID, attempt и result.

## Отзыв и ротация

1. Если есть риск компрометации, отозвать установку внешней интеграции или
   токены в amoCRM.
2. Ротировать `AMO_CLIENT_SECRET`, `TOKEN_ENCRYPTION_KEY` и другие затронутые
   секреты через secret store. Значения не записывать в incident report.
3. Скомпрометированные значения считать недействительными даже при отсутствии
   подтверждённого злоупотребления.

## Возврат в работу

Повторное включение запрещено, пока не закрыта причина инцидента. Перед
возвратом обязательны security/integration тесты, сверка audit, полный
reconciliation и письменное разрешение владельца. Сначала включается только
staging с `SHEET_PUBLISH_ENABLED=false`; production и публикация включаются
отдельными решениями после проверки контрольных итогов.
