# Резервные копии и восстановление

Цель восстановления (RTO) — четыре часа. Проверка восстановления проводится
на изолированной локальной базе и никогда не пишет в production.

## Что резервируется

- управляемые бэкапы Supabase/PostgreSQL (ежедневные, срок хранения — по тарифу);
- миграции в репозитории: схема восстанавливается из кода;
- секреты в secret store владельца — они не входят в дамп базы.

Сырой журнал amoCRM хранится 90 дней и удаляется только с доказательством
(`raw_retention_proofs`). Снимки метрик неизменяемы: восстановление возвращает
ровно те числа, что были опубликованы.

## Репетиция восстановления

```bash
bash scripts/verify-backup-restore.sh --fixture packages/testkit/fixtures/backup.sql
```

Если `psql` не установлен на хосте, укажите способ его запуска явно:

```bash
PSQL_COMMAND="docker exec -i supabase_db_real2-sales-dashboard psql" \
RESTORE_DATABASE_URL="postgresql://postgres:postgres@localhost:5432/postgres" \
bash scripts/verify-backup-restore.sh --fixture packages/testkit/fixtures/backup.sql
```

Скрипт поднимает временную базу, применяет дамп, накатывает миграции и
сверяет контрольную сумму golden-снимка. Он не обращается к production и не
печатает значения секретов.

## Порядок при реальной аварии

1. Остановить воркер: `docker compose ... stop worker`. Публикация и
   синхронизация прекращаются немедленно.
2. Выключить оба флага в `system_controls`, если они были включены.
3. Восстановить базу из последнего бэкапа в новую инстанцию.
4. Накатить миграции и прогнать `pnpm test:integration` против неё.
5. Сверить контрольную сумму текущего снимка с записью в `sheet_publications`.
6. Переключить строку подключения приложения на восстановленную базу.
7. Включить воркер. Флаги остаются выключенными до отдельного решения.

## Чего делать нельзя

- восстанавливать «поверх» работающей базы;
- редактировать строки `metric_*`, `sheet_publications` и `system_alerts`
  вручную: триггеры это запрещают, и обход запрета лишает отчёт доказательства;
- включать `SYNC_ENABLED` или `SHEET_PUBLISH_ENABLED` во время восстановления.
