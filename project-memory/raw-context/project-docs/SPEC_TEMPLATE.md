# Спецификация фичи: {{feature_name}}

> Каждый раздел заполняется конкретными решениями до начала реализации. Фича без заполненных разделов не переходит в implementation plan.

## 1. Описание

Опишите, что делает фича, для какой роли, какую измеримую проблему решает и что сознательно остаётся вне её границ.

## 2. User Stories

Используйте формат: «Как [роль], я хочу [действие], чтобы [результат]». Добавьте основной сценарий, отказ внешнего сервиса, отсутствие данных и сценарий недостаточных прав.

## 3. Модель данных

Для каждой таблицы укажите SQL-имя, поля с SQL-типами, `NOT NULL`, значения по умолчанию, `CHECK`, `UNIQUE`, внешние ключи, индексы, политику хранения и RLS для каждой роли.

## 4. API и серверная логика

Для каждого endpoint укажите method, path, права, query/body schema, успешный ответ, ошибки и идемпотентность. Для фоновой задачи укажите trigger, lock, retry, timeout и результат запуска.

## 5. Экраны и компоненты

Опишите route, компоненты, действия пользователя и четыре обязательных состояния: loading, error, empty, success. Зафиксируйте mobile и desktop поведение.

## 6. Бизнес-логика

Запишите формулы, валидации, приоритеты правил, переходы состояний, часовой пояс, округление и источник истины.

## 7. Крайние случаи

Для каждого случая укажите точное ожидаемое поведение: API недоступен, 401, 429, частичная пагинация, повтор события, изменение справочника, пустой период, конкурентный запуск и повреждённые данные.

## 8. Безопасность и приватность

Опишите разрешённые внешние действия, запрещённые методы, секреты, PII, audit log, RLS и способ доказать, что запрет исполняется.

## 9. Наблюдаемость

Укажите метрики здоровья, структурные логи, trace ID, уровни alert, dashboard freshness и runbook для оператора.

## 10. Тестирование и приёмка

Перечислите unit, contract, integration, RLS, golden и end-to-end тесты с конкретными входами и ожидаемыми результатами. Добавьте измеримый критерий приёмки фичи.

## 11. Зависимости и порядок

Перечислите уже существующие интерфейсы, новые интерфейсы, миграции и фичи, которые могут начаться только после этой.

## 12. Артефакты

Укажите создаваемые файлы, миграции, команды проверки, документацию оператора и доказательства приёмки.
